## 指標
- 正解あり（同梱の2層デモ＋手前文字を合成した画像。正解層は同梱の前景・背景PNG）: `iou`（人物マスクIoU）、`bgHolePSNR`（人物があった範囲の補完背景PSNR）、`ringPSNR`（人物輪郭の外側6px帯＝滲み・ハローの影響）、`shiftPSNR`（人物を5%ずらした合成の正解との一致）、`overlayIoU`（手前文字の検出IoU）、`score`（IoU 40%・補完 30%・ずらし合成 30%の100点換算）。
- 正解なし（雑誌表紙）: `fillSharpRatio`（補完領域/周囲のラプラシアン比。0に近いほどのっぺり）、`skinMissRatio`、`roughness`、`edgeAlign` など。

### 結論と残課題
- 切出し拡大だけでは小さい人物（30〜45%）のIoU 0.87〜0.93 を大きくは伸ばせない。誤りの主因は解像度ではなく、足元の椅子・髪色に近い背景など**意味的な取り違え**で、256px級の単一モデルの限界。
- 実写のユーザー画像での失敗例は未入手のため、実写固有の失敗（髪の毛先、透ける布、背景と同色の服）は未計測。失敗した画像（または症状）が必要。
- 次に効く可能性が高い案（未実装）: 高精度マッティングモデル（例 MODNet/RMBG 系を onnxruntime-web でブラウザ内実行、固定版・配布URL確認が必要）、左右反転・多スケールの推論平均（信頼度マスクの平均）、手動の「ここは人物/背景」ブラシ＋GrabCut型の対話的修正。

## 2026-11-03 文字分離の改善（インク色成分検出）と MODNet 併用

- 事実訂正: Sample1.png（誌面）の実アプリ出力では、改善前は手前層が「加藤玲菜」等の一部しか持たず、背景層に文字が多数残っていた（APP_noMatte/sheet.png、PNGは著作権のため非commit）。
- 原因: `detectGraphicOverlay` は3x3で平坦な成分だけを文字候補にするため、網点・色ムラのある文字（ピンクの縦文字、細い黒太字）と、人物から12%超離れた文字を取りこぼす。
- 対策: 人物マスク外側のインク色（暗色／高彩度）連結成分を追加検出（人物近傍35%まで、線幅≤3%、外接長辺≤20%、輪郭の鋭さ≥0.5）。髪（人物マスク拡張で除外）と暗い机（外接長辺制限）の誤検出を抑制。
- 計測（正解付き）: 文字重ねケースの overlayIoU が heroine 0.282→0.788、city 0.638→0.764、navy 0.594→0.663。非オーバーレイ13件は完全に不変（誤検出なし）。平均スコア 50.4→50.9。magazine の検出面積 4.7%→14.4%。
- 実アプリ（APP_final）: 見出し・縦文字・ロゴ・W杯・日経平均欄が手前層へ移り、背景層から除かれた。
- MODNet併用: 文字のない画像でのみ有効（文字除去跡があるとMODNetが人物内部を欠く例があり、文字ありでは併用しない）。
- 残課題: 小さな本文（約9pt以下）は欠け、「毎日アツイゼ!」の炎文字は背景に暗い滲みが残る、人物前景の右縁と下端に文字断片が残る。

### 追加試験 Q3（暗色しきい値55→90・最小面積14→8）: 不採用

### 追加試験 Q4〜Q6（文字行単位の小文字検出）: 不採用
- 方式: 暗色（<95）の小さな連結成分を、同じ大きさで横または縦に一直線に並ぶものだけ結び、5個以上・細長い行だけを文字として採用（面で広がる塊は除外）。
