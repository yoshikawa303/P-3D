# P-3D Architecture

## 1. 現在の構成

P-3DはGitHub Pagesで配信する静的Webアプリである。

```text
バンドル済みデモ背景＋透過立ち絵 ┐
ユーザー画像 ── 人物／物体マスク ┼─ 透過前景＋端末内擬似補完背景（任意実行）
              └─ MediaPipe人物6カテゴリ分離
                                     └─ 任意Depth Map（白=手前）
  ↓
WebGL image / depth / subject-mask textures
  ↓
前面／背面／選択Webカメラ → MediaPipe Face Landmarker → 鼻位置 + 両目間隔
  ├─ 同じ映像を任意で背景テクスチャへ転送
端末傾き → DeviceOrientation（ユーザー操作で許可・中央合わせ）
  ↓
viewX / viewY / viewZ → WebGL parallax + near/far view
  ├─ 共通エフェクト合成・境界限定ソフトブラー
  ├─ マスク輪郭による非破壊切り抜き・境界フェザー
  └─ alpha輪郭自動リグ → 瞬き／呼吸＋最大12部位の階層ばね → 接地固定の局所UV変形
```

顔追跡が使用できない場合は、ポインタ／タッチドラッグで `viewX` と `viewY` を更新する。

初回起動時は`assets/demos/`内のゆるキャラを`トリックポータル3D`で自動表示する。従来3デモは完成絵、人物／物体を除去した背景JPEG、透過立ち絵PNGで構成し、アクスタ6デモは透過立ち絵PNG、軽量サムネイル、共通背景JPEGで構成する。`u_backgroundTex`と`u_foregroundTex`へ別々に転送し、背景と前景の足元には共通の制限付き視点移動を与える。前景独自の視差と揺れは頭側ほど強く、接地点では0へ減衰させるため、奥行き表現中も背景内の立ち位置から足元が外れない。移動後に露出する領域は背景テクスチャで埋め、単一画像と推定マスクの組合せで生じる被写体の二重像を避ける。透過PNGのalphaを人物／物体マスクとしても使うため、輪郭ガイド、背後影、境界ぼかし、輪郭トリミングへ同じ境界を利用できる。

画面上部の`愛でる`は全セットを順番に切り替え、設定パネルのギャラリーは任意のデモへ直接切り替える。各デモは被写体中心、範囲、立体強度の軽量プリセットを持つが、画像読込後は通常のスライダで変更できる。素材は同一オリジンの静的JPEG／PNGであり、外部画像APIや実行時生成を必要としない。自分の画像を選んだ直後は2層デモ状態と選択表示を解除して単一画像WebGL経路へ戻る。続けて人物自動分離を実行するか人物／物体マスクを読み込み、`背景を補完して2層立体化`を押すと、端末内で透過前景と擬似補完背景へ変換して同じ2層経路を利用する。背景画像と透過キャラ／手前人物PNGは個別のファイル入力から差し替えることもでき、一方だけを選んだ場合は現在のもう一方を維持する。

`assets/demos/`には、完成絵`demo-auto-<slug>.png`、人物なし背景`demo-auto-<slug>-background.png`、透過人物`demo-auto-<slug>-foreground.png`の命名規則で追加デモを置く。`scripts/build_demo_manifest.py`は3ファイルが揃ったセットだけを`assets/demos/auto-demos.js`へ出力し、表示時に既存9件へ自動追加する。不完全なセットは公開一覧へ出さず、任意の`demo-auto-<slug>-thumb.png`があればギャラリーだけ軽量画像を使う。表示名などは`demo-auto-metadata.json`で上書きする。不採用素材は`assets/demo-candidates/`へ分離し、自動走査しない。

背景＋透過人物の表示中は、画像タブの`表示倍率`、`左右位置`、`上下位置`で前景だけを拡大・移動できる。変換はshaderの前景参照UVへ適用し、背景の構図は維持する。Live2D解析ガイド、部位楕円、ボーン点、ボーン線の表示座標にも同じ変換を適用し、配置後の直接編集座標は逆変換して元のリグ定義へ保存する。これにより見た目と編集判定がずれない。

追加した成人の美少女2体／イケメン2体は、768x1152の透過立ち絵と共通ショーケース背景で構成する。既存ゆるキャラ／モフモフ動物の背景除去済み1024x1536 PNGも、同じ共通背景へ載せる別アクスタとして再利用する。ギャラリーだけは256x384の専用サムネイルを使い、初期通信量とデコード負荷を抑える。読込時にalpha外接矩形を計測し、キャラクターの足先最下端をショーケースの回転台中央上面`y=0.795`へ、横幅をケース中央の安全幅へfitした768x1152 canvasを生成する。回転台手前の縁・側面まで下げないため、人物／マスコットが台座へ食い込まず、元素材の余白量が異なっても配置と大きさを背景へ揃えられる。透過PNGは中心alphaと上下左右1 texelのalphaを使って低alphaの色かぶりを内側へ収束させ、生成素材に残るシアン／マゼンタの半透明フリンジを背景へ合成しない。

設定パネルは初期状態で非表示とし、画面右上のボタンで表示／非表示を切り替える。表示状態は`localStorage`の`p3d.settingsPanelVisible.v1`へ保存し、閉じた状態では`visibility: hidden`と`pointer-events: none`で操作対象から外す。Escキーでも閉じられる。内容は`画像`、`Live2D`、`照明`、`背景削除`、`立体表示`、`デバイス`の6タブへ分割し、選択タブを`p3d.settingsTab.v1`へ保存する。パネル外枠をスクロールさせず、選択中タブの内容だけをスクロールする。iPhone相当の狭い画面では高さを54dvh、広い画面では右側の幅420px以内に制限する。認識マスク、中心、範囲、光源の編集ガイドは処理結果との誤認を避けるため初期OFFとし、`編集ガイドを表示`を有効にした場合だけ重ねる。認識ガイドは384角で生成し、従来の160角拡大による粗い表示を抑える。

画像は、画像比率とcanvas比率からWebGLのUVを`contain`方式で補正する。横長画面ではX軸、縦長画面ではY軸のUV範囲を狭め、画像全体の縦横比を維持する。画像と画面の比率が異なる部分は黒い余白として表示する。輪郭切り抜き時も表示比率と参照UVは変更せず、マスク外だけを黒へ合成する。

### 表現モード

- `標準`: 中心位置と範囲から作るガウス分布Depthで、従来どおり滑らかな視差を付ける。
- `ホログラム`: Depth勾配から疑似法線を作り、`viewX / viewY`と疑似光源に追従するFresnel反射、鏡面ハイライト、分光色、色収差視差をfragment shaderで合成する。Depth Map／人物物体マスクがある場合は面方向と対象範囲の精度が上がる。`手前ホロ抑制`は白に近い手前Depthほど材質合成量、分光加算、白ハイライトを弱める。
- `簡易ポップ3D`: 中心Depthをカード状へ強め、視差量、輪郭傾斜の明暗、中央ハイライトを加える。追加のDepth Mapを使わない軽量版であり、隠れた背景の復元や被写体輪郭の正確な立体化は行わない。
- `振動3D（背景固定）`: 背景は元UVで固定し、中心Depthまたは人物／物体マスクの前景だけを微小移動する。従来の白輪郭加算は行わず、移動量と認識境界と強い画像エッジが重なる箇所を共通のソフトブラーへ渡す。
- `Depth多層3D`: Depth値を近景／中景／遠景へ連続的に分け、追従速度の異なる3つの視点値で視差を付ける。人物／物体マスクは前景と背景の境界に使用する。Depth Mapが背景階調を持つ場合は遠景用の遅い視差、寒色の遠方減衰、Depth陰影も背景へ適用する。
- `トリックポータル3D`: 元画像を暗く抑えた外壁、透視変形した窓内背景、疑似光源に追従する額縁、人物／物体前景の順で合成し、被写体が額縁を越えるだまし絵の遮蔽関係を作る。Depth／マスクがない場合も中心近似で動くが、人物自動分離または任意マスクを使うと輪郭精度が上がる。

`背景3層視差`（`bgLayerStrength`、2層素材のみ）は`backgroundLayerUV`で背景UVをDepthに応じて遠景・中景・近景の3帯へ分け、`viewFar`／`viewMid`／`viewNear`に帯別の係数（0.14／0.40／0.72）を掛けた視差をDepth再評価2回で求める。接地点基準の`anchoredMotionWeight`を掛けて足元を固定し、強度0で従来の背景視差と同一になる。キャラは全帯より手前の別面で、近景帯がキャラを遮蔽する処理は行わない。Depth Mapがない場合は中心ガウスDepthで近似する。

全モードは同じ画像テクスチャ、顔追跡、指ドラッグを共有する。通常は6つのプリセットから1つを選ぶ。`複数処理を組み合わせる`を有効にすると、ホログラム、ポップ3D、前景微振動、Depth多層、トリックポータルを独立に選び、各チェック項目の専用強度を0から1で指定できる。Depth多層／微振動／背景透視の座標変位、ポータル額縁と前景越境、Depth照明、ホログラム／浮彫り材質、共通輪郭補正の順に1本のshaderパイプラインで合成する。既存の立体強度は視差移動量として独立させる。

トリックポータル自体は既存shader内の少数サンプルと既存マスクを再利用し、新しいAIモデルや外部画像生成を要求しない。バンドル済み2層デモは完成した背景素材を使う。一枚絵を2層化した場合だけ端末内の擬似背景補完結果を使うため、被写体背後の意味的な復元ではなく、周囲色と低周波構造の連続性を優先する。大きな視差では模様の伸びやぼけが見える可能性があり、ポータル強度と立体強度を抑えて使用する。

### 一枚絵の2層化と擬似背景補完

一枚絵はMediaPipeの人物自動分離結果、または黒背景・白対象の任意マスクを`subjectMaskCanvas`へ保持する。透過PNGをマスクとして読んだ場合はalphaを白黒マスクへ正規化する。`transparentForegroundFromMask`は元画像へこのalphaを掛け、最大1536pxの透過前景を作る。

`pseudoInpaintBackground`は処理負荷を抑えるため最大768pxで動く。人物分離は髪・腕・衣装の縁を取りこぼすため、マスクを画像長辺の4%（最小10px）まで`dilateHoleByDistance`で円形に広げ、背景側へ人物の輪郭が残らないようにする。欠損画素は`pushPullFill`で、確定背景を粗い解像度へ集約して穴へ補間で戻すpush-pull方式により、周囲から滑らかに連続させる（境界色の方向伝播による格子状の滲みを避ける）。確定背景画素は変更しない。

これは画像の意味を推論する生成AI Inpaintingではなく、端末内の決定的な近傍色補完である。文字、建物、家具、反復模様などを被写体の背後へ正しく再構成する保証はなく、広い欠損や大きな視差ではぼけ・伸びが見える。画像データは外部サーバーへ送信しない。将来、実生成AIを使う場合は、送信先、利用規約、画像保持、資格情報、オプトインUIを別仕様として承認する。

### 動くアクスタの輪郭自動リグと簡易重力モーション

背景＋透過立ち絵を持つ全9デモの読込時に、透過alphaの外接矩形、縦横比、重心から基準領域と足元接地点を自動推定し、`activeRigProfile`と`activeRigParts`へ設定する。人物として分類した5デモは従来の`頭`、左右の腕・手、`上半身`、左右の脚に`髪`を加えた9部位を生成する。制作側で`chestMotion:true`を明示した女性デモ3件だけは`胸`も加えた10部位とし、男性デモは`chestMotion:false`、任意画像は既定falseとする。画像から性別を推測して胸部を自動付与しない。左／右はキャラクター本人基準であり、正面画像では画面上の左右と反転する。動物／マスコット／モノの4デモは胴体、頭部・顔、髪・耳・布、付属部位の4領域を生成し、付属部位は既定で小物の剛体移動にする。JavaScript側は最大12部位の位置・速度状態を持ち、体幹、柔らかい揺れ、顔、目、口、髪、手、胸、腰・臀部、小物、尻尾のプリセットから部位ごとに選択して積分する。`胸部弾性（2軸遅延）`は親の速度と異なるX/Y周期を入力へ加える柔らかい二軸遅延プリセットで、実素材の骨格・質量を推定する物理シミュレーションではない。最大変位はUVの1.6%以内に制限し、計算はフレーム間の経過秒で正規化する。設定の`重力・揺れ強度`は全入力を0〜1で調整し、初期値は0.75。`Live2D風自動認識モーション`は初期ON、`prefers-reduced-motion`時は停止する。

fragment shaderでは透過立ち絵のalphaを対象マスクにし、4つのcore領域と最大8つの追加領域を重ねる。通常の柔体領域は中心から輪郭へ連続減衰させる一方、`小物（剛体移動）`は領域内の約90%へほぼ一定の変位を与え、輪郭付近だけをなじませる。これにより単一テクスチャという制約内でも小物内部の伸縮を抑える。人物ではcoreを上半身、頭、左腕、右腕へ割り当て、追加領域を左右の手・脚、髪、許可済み胸部へ割り当てる。頭領域内へ目・口の帯を推定し、不規則な間隔の自動瞬き、上半身または胴体へ呼吸の横伸縮、頭へ視線方向の傾斜を加える。無発話時の口は閉じ、体幹と胸は約13.2回／分の共通呼吸位相を使い、胸だけに小さな遅延と第2高調波を加える。手動追加した目・口には専用の低振幅追従プリセットを選択できる。体幹の揺れは接地点からの高さに応じて0から1へ増やし、足元のUVを動かさない。各部位の局所変位を単一のUVへ1回サンプリングするため、同じ人物を複数枚重ねる方式より二重輪郭が出にくい。全モードで移動後alphaを最終マスクへ使用し、元位置のシルエットを再描画しない。アクリル表現は外周の着色を行わず、被写体内側を横切る弱い反射だけを加える。背後影は全身外周ではなく接地する足元へ限定する。

背景付き素材の座標系は、透過輪郭の最下端を`groundAnchor`、人型／幅広形状別の許容量を`motionRange`とする。背景と前景の接地点へ同じ遠景視差を適用し、前景独自の視差は接地点で遠景視差と一致させる。`トリックポータル3D`の背景台形変形も画像中心ではなく接地点を固定軸にし、上方ほど強く動かす。これは「背景を動かす」と「背景内の立ち位置範囲へ適合する」を組み合わせた方式である。背景の実レイヤー分割はさらに立体感を上げられるが、既存の1枚背景には奥行き別素材がないため将来の素材拡張とする。

これは1枚の透過立ち絵へ認識領域別の連続変形を掛けるLive2D風疑似リグであり、目、口、腕や隠れ部分を独立RGBAレイヤーへ実分割したLive2Dモデルではない。大きく動かすと顔や服が伸びるため、ばね変位をUVの1.6%以内に制限する。将来の半自動パーツ分割が導入された場合も、このばね状態は各実レイヤーの入力として再利用できる。

腕・脚・手が交差する画像では、Pose Landmarkerが見えている関節の左右ラベルを返しても、隠れた画素の前後順を単一透過テクスチャから復元できない。美少女デモの`左手＋ティーカップ`と`右腕`も影響域を別々に動かすことはできるが、画素を独立RGBA層へ分離して前後順を入れ替える処理ではない。正しい交差遮蔽には、手＋小物、腕、胴体などの別素材と部位別マスク／z順を入力する次段階のパーツレイヤー機能が必要である。

`裸眼3D強調`は、`画面面Depth`をゼロ視差面としてDepth値との差を視差へ変換する。これにより手前と奥が同じ方向へずれる平面移動を避け、画面面より手前は視点と逆、奥は視点と同方向へ相対移動する。移動後の人物マスクを9タップで再評価して動的遮蔽を作り、低解像度マスクの階段状輪郭を抑える。さらに被写体背後の接地影と画面端に固定した弱い空間陰影を加え、表示面を窓として知覚しやすくする。

Face Landmarkerの両目間隔は追跡開始時を基準値とし、顔が近づいた／離れた割合を`viewZ`へ変換する。`前後視点`スライダは同じ経路を手動確認できる。X／Y／Zと近景／中景／遠景の追従値は、固定割合ではなくフレーム間の経過秒から指数平滑係数を求めるため、60Hzと120Hzで追従時間が大きく変わらない。`prefers-reduced-motion`時は自動の前後追跡を止め、手動値だけを使用する。

これは通常ディスプレイで1人の視点に合わせるHead-Coupled Perspectiveである。左右眼へ独立画像を提示する光学系は使わないため、両眼視差を持つ真の裸眼ステレオは提供しない。

共通輪郭補正は、透過立ち絵の中心alphaと上下左右1 texelの平均を使う内向きalpha整形と、移動後マスクの9タップ平滑化で行う。処理済み画像へ元の合成画像を色ブラーとして再混合しないため、移動前背景や透過端の色を輪郭へ戻さない。Depth多層もDepth境界そのものの白い発光や暗線を足さず、面法線による照明だけを使う。強度は`輪郭ノイズ除去`で0から1まで調整可能にする。

疑似照明は設定した光源X／YとDepth疑似法線の内積から、光源側の鏡面ハイライトと制御された白飛び、反対側の陰影を求める。Depth境界は輪郭光として追加し、`光・陰影強度`で一括調整する。これは元画像から光源を推定する処理ではなく、ユーザーが指定する演出用の疑似光源である。

### Depth Map・人物／物体マスク

- Depth Mapはグレースケール画像を端末内で読み込み、黒を遠方、白を手前として扱う。
- 人物／物体マスクは黒を背景、白を対象として扱う。newMosaic、画像編集ソフト、任意のセグメンテーション処理が生成したPNGを共通入力にできる。
- `人物を自動分離`は、選択済み画像をMediaPipe Image Segmenterへ渡し、背景、髪、身体の肌、顔の肌、服、その他の6カテゴリを端末内で推論する。髪、身体の肌、顔の肌、服を基準に1px収縮後の主被写体を1px復元し、離れた文字や背景小物の誤検知を除外する。結果画像はサーバーへ送信しない。
- 自動人物分離は髪・肌・顔・服から主被写体を抽出した後、人物へ接する小さな`その他`領域を髪飾り・手持ち小物候補として追加し、外周背景から到達できない内部穴を前景へ戻す。大きな背景小物は面積上限で除外する。マスクと人物部位Depthを作った後、そのまま透過前景・擬似補完背景の生成へ進む。任意マスクは`背景を補完して2層立体化`を明示的に押した場合に同じ処理へ進む。認識範囲が画像の1%未満または92%超の場合は誤分離として2層化を拒否する。
- newMosaicの`VNGeneratePersonInstanceMaskRequest`、Vision骨格、macOS用ONNX RuntimeをGitHub Pagesから直接実行することはできない。P-3Dとはマスク／Depth画像を境界として連携し、Safari側の自動人物分離にはWeb対応MediaPipeモデルを使う。
- 任意マスクは人物以外の物体にも使用できる。自動分離は人物用モデルであり、一般物体を自動認識するものではない。

### 編集ガイド・簡易編集

- 設定表示中だけ、WebGLとは別の透明canvasへキャラ中心／範囲、疑似光源から中心へ向かうRayを描く。キャラ中心と光源の丸いハンドルは画像上で直接ドラッグでき、対応するX／Yスライダへ即時反映する。
- 人物自動分離または任意マスク読込後は、マスクの内部を薄い水色、実輪郭を濃い水色で重ねる。これは認識結果の確認用であり、マスク自体を変更しない。
- `認識マスクの輪郭で切り抜く`は人物／物体マスクを9タップで平滑化し、マスク外をshaderの最終段で黒へ合成する。矩形の上下左右トリミングは使用せず、`輪郭ぼかし`をフェザー幅として渡す。
- Undo／Redoは画像やAIマップを複製せず、エフェクトごとの強度、照明、中心、範囲、輪郭切り抜き等の編集値を最大60状態保持する。ガイドのドラッグ完了と初期値リセットも履歴へ積まれるためUndo可能である。

### Live2D解析デバッグ

- `解析レイヤを表示・編集`は通常表示へ影響しない初期OFFの開発用表示である。ON時は、背景素材、透過キャラ素材、認識マスク、奥行き認識範囲、部位ワイヤー、推定ボーン、認識タグ番号を個別に表示／非表示へ切り替えられる。
- `解析レイヤを表示・編集`がONで有効な疑似リグがある間は、設定パネルを閉じてもoverlay描画と部位中心・サイズハンドル・ボーンポイントの直接ドラッグを維持する。iPhone／iPadでは設定パネルで対象を選択してから閉じ、画像全体を見ながら編集できる。通常のキャラ中心／光源ガイドは従来どおり設定パネル表示中だけ操作可能とし、解析デバッグOFF時に意図しない編集領域を残さない。
- 背景／キャラの元素材確認では通常の材質・影・輪郭トリミングを外し、WebGLで実際に使用している移動後の`backgroundUV`／`foregroundUV`から両素材を独立合成する。背景のみ、キャラのみ、両方なしを確認でき、デバッグOFF時は従来のエフェクト合成へ戻る。
- 人物は`TAG 01 頭`から`TAG 08 脚 右`までの基本部位に`TAG 09 髪`を追加し、許可済み女性デモだけ`TAG 10 胸`も初期表示する。人物以外は`TAG 01 胴体`、`TAG 02 頭部・顔`、`TAG 03 髪・耳・布`、`TAG 04 付属部位`を使う。最大12部位はWebGL 1の固定uniform上限として管理し、4つのcore領域に加えて追加8領域をshaderへ渡す。ワイヤー楕円とボーンは`activeRigParts`、`rigSprings`、視点／Depth視差、振動、呼吸状態を毎フレーム参照し、Live2D風モーションへ追随する。
- 部位は常時表示のリストから選択し、追加／削除／複製できる。中心はプレビューの円内ドラッグ、範囲幅／高さは選択楕円の左右／上下ハンドル、角度は上側の丸い回転ハンドルで直接補正する。Shiftを押した回転は15°刻みに固定する。編集は元画像や推定基準を破壊せず、Undo／Redoと`選択部位を復元`を利用できる。デモを再読込するか`リグ全体を自動推定へ戻す`と初期推定値へ戻る。
- 各部位は親部位、親モーション継承ON/OFF、継承量を持つ。人物の初期関係は上半身→頭・左右腕・左右脚、左右腕→各手とする。人物以外は胴体→頭部、頭部→髪／布／耳、胴体→小物／尻尾を維持する。子の独立ばねへ親の合成後変位を加算し、親候補から子孫を除外して保存時にも循環参照を拒否する。影響域が重なるだけでは主従関係を推定せず、明示的な親子設定だけがモーションを伝播する。
- ボーンは`activeBonePoints`へ最大24ポイントを保持する。人物は骨盤を起点に、腰、背骨、首、頭頂、左右の肩・肘・手首・股関節・膝・足首からなる17ポイントを初期生成する。人物以外は接地点の起点、胴体／頭部の関節、髪・布の分岐、小物の終点からなる5ポイントを維持する。各ポイントは名称、種類、親ポイント、追随部位、追随率を持ち、起点追加、選択ポイントの子追加、削除、プレビュー上の直接ドラッグに対応する。線を選択すると接続線と端点を強調し、中点分割で親子間へ新しいポイントを挿入する。選択点と接続線は表示領域の短辺に応じて強調倍率を上げる。削除時は直下の子を削除ポイントの親へつなぎ直し、循環する親候補は選択肢から除外する。追随座標は割り当てた部位の合成後変位へ追随率を掛けて算出するため、編集中の線と点はアニメーション中も同じ動作へ追随する。認識タグ番号は初期OFFとする。
- `P3D-PseudoLive2D-Rig` version 1 JSONは最大12部位の領域・物理設定・親子関係と最大24ボーンポイントを保存する。読込時はID形式、件数上限、参照先、循環、起点、画像外座標を検証し、画像データ自体は含めない。リグ全体の定義は既存の最大60状態のUndo／Redoへ含める。
- 人物デモと2層化した一枚絵はPose Landmarkerの実ランドマークを優先し、検出失敗時だけ透過シルエット外接矩形へフォールバックする。腕を上げる、膝を曲げるなどで検出が外れた場合は、ワイヤー範囲とボーン点を直接ドラッグして補正する。透過キャラ層を作っていない単一画像では安全な部位変形ができないため、リグ編集は無効とし、Depth／マスクの従来ガイドだけを使用する。これはCubismのArtMesh、デフォーマ、パラメータ、キーフォーム、PSDパーツ分割を編集する機能ではない。

振動3Dは`requestAnimationFrame`ごとに時刻をshaderへ渡すため、60Hz／120Hzなど端末とブラウザの実効描画更新へ追従する。120fpsをコード側で固定保証はしない。背景は固定し、前景だけを横・縦・速さの独立設定で動かす。最大振幅は横UV 0.24%、縦0.08%、周波数は横約3.2〜5.4Hz、縦はその0.79倍とし、既定値では横約0.086%、縦約0.021%まで抑える。2層素材では接地点へ向けて振幅を0にし、`prefers-reduced-motion`が有効な場合は振動成分だけを0にする。顔／指による前景視差は維持する。

## 2. カメラ・顔追跡の開始順

```text
ボタンのユーザー操作
  ↓
Secure Context / mediaDevices確認
  ↓
選択deviceId、またはfacingMode: user / environment
  ↓
video.play() → enumerateDevices()でPCを含む利用可能カメラ名を更新
  ↓
MediaPipe JavaScript module + WASM + model読込
  ↓
GPUでFaceLandmarker生成
  ├─ 成功 → VIDEO検出
  └─ 失敗 → CPUで再生成
```

カメラ要求を外部モジュール読込より先に置く。これにより、CDNやWASMが失敗してもカメラ権限処理へ到達し、原因を分離して表示できる。

## 3. 外部依存

|用途|固定参照|
|---|---|
|MediaPipe module|`@mediapipe/tasks-vision@1.0.1/vision_bundle.mjs`|
|MediaPipe WASM|`@mediapipe/tasks-vision@1.0.1/wasm`|
|Face Landmarker model|Google Storageの`face_landmarker/float16/1`|

依存を更新する場合は、配布URLがHTTP 200であること、API互換性、iPhone Safari実機を確認する。

## 4. 状態の分離

- `cameraOn`: カメラstreamとvideo再生が開始済み。
- `cameraDevice` / `cameraFacing`: 明示選択したWebカメラ、または前面／背面の希望方向。顔追跡と背景映像は同じstreamを共有する。
- `cameraBackgroundTex` / `cameraAspect`: 選択カメラの各フレームとアスペクト比。2層表示の背景だけへ合成し、前面カメラ時は鏡像にする。
- `trackingOn`: Face Landmarkerが初期化済みでフレーム検出可能。
- `startingFace`: 起動処理の多重実行を防止。
- `hasDepthMap` / `hasSubjectMask`: 任意または人物自動分離で生成した補助テクスチャの有無。
- `nearView` / `midView` / `farView`: 同じ顔／ドラッグ視点へ異なる追従係数を適用した多層視差状態。
- `targetZ` / `viewZ` / `faceScaleBaseline`: 両目間隔から求めた顔の前後移動と平滑化状態。
- `pointerTarget` / `gazeTarget` / `tiltTarget`: 指・マウス、選択カメラの顔位置、DeviceOrientationの傾きを分離保持し、`viewInputMode`で一つを視点目標へ選ぶ。傾きはユーザー操作で許可し、現在角度を中央へ再校正できる。
- `recognitionBounds` / `recognitionGuideCanvas` / `subjectMaskCanvas`: 人物／物体マスクから得た確認用ガイドと、任意画像を2層化するため端末内に保持する白黒マスク。
- `guideHandles` / `guideDragTarget`: キャラ中心・光源の画面座標とドラッグ対象。
- `undoStack` / `redoStack`: 非破壊編集値の履歴。画像、Depth、マスク本体は含めない。
- `DEMO_ASSETS` / `activeDemoIndex`: 完成絵、背景、透過立ち絵のURL、表示名、推奨中心・範囲・立体強度と現在の選択状態。
- `hasLayeredDemo`: 背景と透過立ち絵の独立テクスチャを使う状態。バンドル済みデモと、一枚絵から端末内生成した2層の両方で有効にする。無効時は従来の単一画像経路を使う。
- `activeRigProfile` / `activeRigParts` / `activeMotionRange`: 全2層デモの基準影響域、編集可能な最大12部位と親子・モーション設定、接地点、背景内の許容稼働範囲。
- `activeStandee`: アクスタ固有のアクリル材質表現だけを有効にする現在デモの状態。Live2D風モーションの有効条件には使わない。
- `rigSprings`: 人物9〜10部位または人物以外の4部位それぞれの位置と速度。画像データや編集履歴には含めず、デモ切替時にゼロへ戻す。
- `inferredRigProfile` / `inferredRigParts`: 現在素材から得た自動推定の基準値。編集後の状態と比較して手動補正状態を表示し、部位単位の復元元に使う。
- `RIG_PARTS` / `MOTION_PRESETS` / `live2dVisualState`: 標準TAGの表示名・色、部位別アルゴリズムの初期物性、瞬き／口元／視線／呼吸の現在値。デバッグoverlayは`rigSprings`と併せて毎フレーム参照する。
- カメラ失敗: 手動モードへ戻してカメラ再試行を提示。
- 顔検出準備失敗: カメラを停止せず、手動操作と顔追跡再試行を提示。
