# P-3D Architecture

## 1. 現在の構成

P-3DはGitHub Pagesで配信する静的Webアプリである。

```text
バンドル済みデモ背景＋透過立ち絵 ┐
ユーザー画像 ────────────────────┴─ 任意Depth Map（白=手前）
                                     ├─ 任意人物／物体マスク（白=対象）
                                     └─ MediaPipe人物6カテゴリ分離（任意実行）
  ↓
WebGL image / depth / subject-mask textures
  ↓
フロントカメラ → MediaPipe Face Landmarker → 鼻位置 + 両目間隔
  ↓
viewX / viewY / viewZ → WebGL parallax + near/far view
  ├─ 共通エフェクト合成・境界限定ソフトブラー
  ├─ マスク輪郭による非破壊切り抜き・境界フェザー
  └─ alpha輪郭自動リグ → 瞬き／呼吸＋最大8部位の階層ばね → 接地固定の局所UV変形
```

顔追跡が使用できない場合は、ポインタ／タッチドラッグで `viewX` と `viewY` を更新する。

初回起動時は`assets/demos/`内のゆるキャラを`トリックポータル3D`で自動表示する。従来3デモは完成絵、人物／物体を除去した背景JPEG、透過立ち絵PNGで構成し、アクスタ6デモは透過立ち絵PNG、軽量サムネイル、共通背景JPEGで構成する。`u_backgroundTex`と`u_foregroundTex`へ別々に転送し、背景と前景の足元には共通の制限付き視点移動を与える。前景独自の視差と揺れは頭側ほど強く、接地点では0へ減衰させるため、奥行き表現中も背景内の立ち位置から足元が外れない。移動後に露出する領域は背景テクスチャで埋め、単一画像と推定マスクの組合せで生じる被写体の二重像を避ける。透過PNGのalphaを人物／物体マスクとしても使うため、輪郭ガイド、背後影、境界ぼかし、輪郭トリミングへ同じ境界を利用できる。

画面上部の`愛でる`は9セットを順番に切り替え、設定パネルのギャラリーは任意のデモへ直接切り替える。各デモは被写体中心、範囲、立体強度の軽量プリセットを持つが、画像読込後は通常のスライダで変更できる。素材は同一オリジンの静的JPEG／PNGであり、外部画像APIや実行時生成を必要としない。自分の画像を選んだ場合は2層デモ状態と選択表示を解除し、従来の単一画像WebGL経路へ戻す。

追加した成人の美少女2体／イケメン2体は、768x1152の透過立ち絵と共通ショーケース背景で構成する。既存ゆるキャラ／モフモフ動物の背景除去済み1024x1536 PNGも、同じ共通背景へ載せる別アクスタとして再利用する。ギャラリーだけは256x384の専用サムネイルを使い、初期通信量とデコード負荷を抑える。読込時にalpha外接矩形を計測し、キャラクターの足先最下端をショーケースの回転台中央上面`y=0.795`へ、横幅をケース中央の安全幅へfitした768x1152 canvasを生成する。回転台手前の縁・側面まで下げないため、人物／マスコットが台座へ食い込まず、元素材の余白量が異なっても配置と大きさを背景へ揃えられる。透過PNGは中心alphaと上下左右1 texelのalphaを使って低alphaの色かぶりを内側へ収束させ、生成素材に残るシアン／マゼンタの半透明フリンジを背景へ合成しない。

設定パネルは初期状態で非表示とし、画面右上のボタンで表示／非表示を切り替える。表示状態は`localStorage`の`p3d.settingsPanelVisible.v1`へ保存し、閉じた状態では`visibility: hidden`と`pointer-events: none`で操作対象から外す。Escキーでも閉じられる。内容は`画像`、`Live2D`、`照明`、`トリミング`、`立体表示`、`デバイス`の6タブへ分割し、選択タブを`p3d.settingsTab.v1`へ保存する。パネル外枠をスクロールさせず、選択中タブの内容だけをスクロールする。iPhone相当の狭い画面では高さを54dvh、広い画面では右側の幅420px以内に制限する。認識マスク、中心、範囲、光源の編集ガイドは処理結果との誤認を避けるため初期OFFとし、`編集ガイドを表示`を有効にした場合だけ重ねる。認識ガイドは384角で生成し、従来の160角拡大による粗い表示を抑える。

画像は、画像比率とcanvas比率からWebGLのUVを`contain`方式で補正する。横長画面ではX軸、縦長画面ではY軸のUV範囲を狭め、画像全体の縦横比を維持する。画像と画面の比率が異なる部分は黒い余白として表示する。輪郭切り抜き時も表示比率と参照UVは変更せず、マスク外だけを黒へ合成する。

### 表現モード

- `標準`: 中心位置と範囲から作るガウス分布Depthで、従来どおり滑らかな視差を付ける。
- `ホログラム`: Depth勾配から疑似法線を作り、`viewX / viewY`と疑似光源に追従するFresnel反射、鏡面ハイライト、分光色、色収差視差をfragment shaderで合成する。Depth Map／人物物体マスクがある場合は面方向と対象範囲の精度が上がる。`手前ホロ抑制`は白に近い手前Depthほど材質合成量、分光加算、白ハイライトを弱める。
- `簡易ポップ3D`: 中心Depthをカード状へ強め、視差量、輪郭傾斜の明暗、中央ハイライトを加える。追加のDepth Mapを使わない軽量版であり、隠れた背景の復元や被写体輪郭の正確な立体化は行わない。
- `振動3D（背景固定）`: 背景は元UVで固定し、中心Depthまたは人物／物体マスクの前景だけを微小移動する。従来の白輪郭加算は行わず、移動量と認識境界と強い画像エッジが重なる箇所を共通のソフトブラーへ渡す。
- `Depth多層3D`: Depth値を近景／中景／遠景へ連続的に分け、追従速度の異なる3つの視点値で視差を付ける。人物／物体マスクは前景と背景の境界に使用する。Depth Mapが背景階調を持つ場合は遠景用の遅い視差、寒色の遠方減衰、Depth陰影も背景へ適用する。
- `トリックポータル3D`: 元画像を暗く抑えた外壁、透視変形した窓内背景、疑似光源に追従する額縁、人物／物体前景の順で合成し、被写体が額縁を越えるだまし絵の遮蔽関係を作る。Depth／マスクがない場合も中心近似で動くが、人物自動分離または任意マスクを使うと輪郭精度が上がる。

全モードは同じ画像テクスチャ、顔追跡、指ドラッグを共有する。通常は6つのプリセットから1つを選ぶ。`複数処理を組み合わせる`を有効にすると、ホログラム、ポップ3D、前景微振動、Depth多層、トリックポータルを独立に選び、各チェック項目の専用強度を0から1で指定できる。Depth多層／微振動／背景透視の座標変位、ポータル額縁と前景越境、Depth照明、ホログラム／浮彫り材質、共通輪郭補正の順に1本のshaderパイプラインで合成する。既存の立体強度は視差移動量として独立させる。

トリックポータルは既存shader内の少数サンプルと既存マスクを再利用し、新しいAIモデル、外部画像生成、背景Inpaintingを要求しない。そのためGitHub Pagesだけで利用できる。一方、元画像に写っていない遮蔽背景は復元しないため、大きな視差では画像端の反復や引き伸ばしが見える可能性があり、ポータル強度と立体強度を抑えて使用する。

### 動くアクスタの輪郭自動リグと簡易重力モーション

背景＋透過立ち絵を持つ全9デモの読込時に、透過alphaの外接矩形、縦横比、重心から頭、顔、胴体、髪／耳／布、小物／尻尾の楕円影響域と足元接地点を自動推定し、`activeRigProfile`と`activeRigParts`へ設定する。人型と幅広の動物／マスコット／物体で頭部・胴体比率を切り替える軽量なシルエット推定であり、追加AIモデルや通信を必要としない。JavaScript側は最大8部位の位置・速度状態を持ち、部位ごとのモーションON/OFF、強度、重力、ばね、減衰、アルゴリズムで積分する。`胸部弾性（2軸遅延）`は親の速度と異なるX/Y周期を入力へ加える柔らかい二軸遅延プリセットで、実素材の骨格・質量を推定する物理シミュレーションではない。最大変位はUVの1.6%以内に制限し、計算はフレーム間の経過秒で正規化する。設定の`重力・揺れ強度`は全入力を0〜1で調整し、初期値は0.75。`Live2D風自動認識モーション`は初期ON、`prefers-reduced-motion`時は停止する。

fragment shaderでは透過立ち絵のalphaを対象マスクにし、頭、胴体、髪／布／耳、小物／尻尾の楕円影響域を滑らかに重ねる。頭領域内へ目・口の帯を推定して自動瞬きと口元の局所伸縮、胴体へ呼吸の横伸縮、頭へ視線方向の傾斜を加える。胴体の揺れは接地点からの高さに応じて0から1へ増やし、足元のUVを動かさない。各部位の局所変位を単一のUVへ1回サンプリングするため、同じ人物を複数枚重ねる方式より二重輪郭が出にくい。全モードで移動後alphaを最終マスクへ使用し、元位置のシルエットを再描画しない。アクリル表現は外周の着色を行わず、被写体内側を横切る弱い反射だけを加える。背後影は全身外周ではなく接地する足元へ限定する。

背景付き素材の座標系は、透過輪郭の最下端を`groundAnchor`、人型／幅広形状別の許容量を`motionRange`とする。背景と前景の接地点へ同じ遠景視差を適用し、前景独自の視差は接地点で遠景視差と一致させる。`トリックポータル3D`の背景台形変形も画像中心ではなく接地点を固定軸にし、上方ほど強く動かす。これは「背景を動かす」と「背景内の立ち位置範囲へ適合する」を組み合わせた方式である。背景の実レイヤー分割はさらに立体感を上げられるが、既存の1枚背景には奥行き別素材がないため将来の素材拡張とする。

これは1枚の透過立ち絵へ認識領域別の連続変形を掛けるLive2D風疑似リグであり、目、口、腕や隠れ部分を独立RGBAレイヤーへ実分割したLive2Dモデルではない。大きく動かすと顔や服が伸びるため、ばね変位をUVの1.6%以内に制限する。将来の半自動パーツ分割が導入された場合も、このばね状態は各実レイヤーの入力として再利用できる。

`裸眼3D強調`は、`画面面Depth`をゼロ視差面としてDepth値との差を視差へ変換する。これにより手前と奥が同じ方向へずれる平面移動を避け、画面面より手前は視点と逆、奥は視点と同方向へ相対移動する。移動後の人物マスクを9タップで再評価して動的遮蔽を作り、低解像度マスクの階段状輪郭を抑える。さらに被写体背後の接地影と画面端に固定した弱い空間陰影を加え、表示面を窓として知覚しやすくする。

Face Landmarkerの両目間隔は追跡開始時を基準値とし、顔が近づいた／離れた割合を`viewZ`へ変換する。`前後視点`スライダは同じ経路を手動確認できる。X／Y／Zと近景／中景／遠景の追従値は、固定割合ではなくフレーム間の経過秒から指数平滑係数を求めるため、60Hzと120Hzで追従時間が大きく変わらない。`prefers-reduced-motion`時は自動の前後追跡を止め、手動値だけを使用する。

これは通常ディスプレイで1人の視点に合わせるHead-Coupled Perspectiveである。左右眼へ独立画像を提示する光学系は使わないため、両眼視差を持つ真の裸眼ステレオは提供しない。

共通輪郭補正は、透過立ち絵の中心alphaと上下左右1 texelの平均を使う内向きalpha整形と、移動後マスクの9タップ平滑化で行う。処理済み画像へ元の合成画像を色ブラーとして再混合しないため、移動前背景や透過端の色を輪郭へ戻さない。Depth多層もDepth境界そのものの白い発光や暗線を足さず、面法線による照明だけを使う。強度は`輪郭ノイズ除去`で0から1まで調整可能にする。

疑似照明は設定した光源X／YとDepth疑似法線の内積から、光源側の鏡面ハイライトと制御された白飛び、反対側の陰影を求める。Depth境界は輪郭光として追加し、`光・陰影強度`で一括調整する。これは元画像から光源を推定する処理ではなく、ユーザーが指定する演出用の疑似光源である。

### Depth Map・人物／物体マスク

- Depth Mapはグレースケール画像を端末内で読み込み、黒を遠方、白を手前として扱う。
- 人物／物体マスクは黒を背景、白を対象として扱う。newMosaic、画像編集ソフト、任意のセグメンテーション処理が生成したPNGを共通入力にできる。
- `人物を自動分離`は、選択済み画像をMediaPipe Image Segmenterへ渡し、背景、髪、身体の肌、顔の肌、服、その他の6カテゴリを端末内で推論する。自動人物マスクには髪、身体の肌、顔の肌、服だけを採用し、1px収縮後の最大8連結領域を主被写体として1px復元することで、離れた文字や背景小物の誤検知を除外する。結果画像はサーバーへ送信しない。
- newMosaicの`VNGeneratePersonInstanceMaskRequest`、Vision骨格、macOS用ONNX RuntimeをGitHub Pagesから直接実行することはできない。P-3Dとはマスク／Depth画像を境界として連携し、Safari側の自動人物分離にはWeb対応MediaPipeモデルを使う。
- 任意マスクは人物以外の物体にも使用できる。自動分離は人物用モデルであり、一般物体を自動認識するものではない。

### 編集ガイド・簡易編集

- 設定表示中だけ、WebGLとは別の透明canvasへキャラ中心／範囲、疑似光源から中心へ向かうRayを描く。キャラ中心と光源の丸いハンドルは画像上で直接ドラッグでき、対応するX／Yスライダへ即時反映する。
- 人物自動分離または任意マスク読込後は、マスクの内部を薄い水色、実輪郭を濃い水色で重ねる。これは認識結果の確認用であり、マスク自体を変更しない。
- `認識マスクの輪郭で切り抜く`は人物／物体マスクを9タップで平滑化し、マスク外をshaderの最終段で黒へ合成する。矩形の上下左右トリミングは使用せず、`輪郭ぼかし`をフェザー幅として渡す。
- Undo／Redoは画像やAIマップを複製せず、エフェクトごとの強度、照明、中心、範囲、輪郭切り抜き等の編集値を最大60状態保持する。ガイドのドラッグ完了と初期値リセットも履歴へ積まれるためUndo可能である。

### Live2D解析デバッグ

- `解析レイヤを表示・編集`は通常表示へ影響しない初期OFFの開発用表示である。ON時は、背景素材、透過キャラ素材、認識マスク、奥行き認識範囲、部位ワイヤー、推定ボーン、認識タグ番号を個別に表示／非表示へ切り替えられる。
- 背景／キャラの元素材確認では通常の材質・影・輪郭トリミングを外し、WebGLで実際に使用している移動後の`backgroundUV`／`foregroundUV`から両素材を独立合成する。背景のみ、キャラのみ、両方なしを確認でき、デバッグOFF時は従来のエフェクト合成へ戻る。
- 自動リグの4領域を`TAG 01 胴体`、`TAG 02 頭部・顔`、`TAG 03 髪・耳・布`、`TAG 04 小物・尻尾`として初期表示し、追加部位へTAG 05〜08を割り当てる。最大8部位はWebGL 1の固定uniform上限として管理し、標準4領域に加えて追加4領域をshaderへ渡す。ワイヤー楕円とボーンは`activeRigParts`、`rigSprings`、視点／Depth視差、振動、呼吸状態を毎フレーム参照し、Live2D風モーションへ追随する。
- 部位は常時表示のリストから選択し、追加／削除／複製できる。中心はプレビューの円内ドラッグ、範囲幅／高さは選択楕円の左右／上下ハンドルを直接ドラッグして補正するため、座標・サイズの設定スライダは持たない。編集は元画像や推定基準を破壊せず、Undo／Redoと`選択部位を復元`を利用できる。デモを再読込するか`リグ全体を自動推定へ戻す`と初期推定値へ戻る。
- 各部位は親部位、親モーション継承ON/OFF、継承量を持つ。初期関係は胴体→頭部、頭部→髪／布／耳、胴体→小物／尻尾で、子の独立ばねへ親の合成後変位を加算する。親候補から子孫を除外し、保存時にも循環参照を拒否する。影響域が重なるだけでは主従関係を推定せず、明示的な親子設定だけがモーションを伝播する。
- ボーンは`activeBonePoints`へ最大24ポイントを保持する。初期構造は接地点の起点、胴体／頭部の関節、髪・布の分岐、小物の終点である。各ポイントは名称、種類、親ポイント、追随部位、追随率を持ち、起点追加、選択ポイントの子追加、削除、プレビュー上の直接ドラッグに対応する。削除時は直下の子を削除ポイントの親へつなぎ直し、循環する親候補は選択肢から除外する。追随座標は割り当てた部位の合成後変位へ追随率を掛けて算出するため、編集中の線と点はアニメーション中も同じ動作へ追随する。
- `P3D-PseudoLive2D-Rig` version 1 JSONは最大8部位の領域・物理設定・親子関係と最大24ボーンポイントを保存する。読込時はID形式、件数上限、参照先、循環、起点、画像外座標を検証し、画像データ自体は含めない。リグ全体の定義は既存の最大60状態のUndo／Redoへ含める。
- 現在のタグとボーンは透過シルエットから得る軽量な推定領域であり、画像内の実在関節を姿勢推定モデルで検出した結果ではない。透過キャラ層を持たない任意の単一画像では、背景復元なしに安全な部位変形ができないため、リグ編集は無効とし、Depth／マスクの従来ガイドだけを使用する。これはCubismのArtMesh、デフォーマ、パラメータ、キーフォーム、PSDパーツ分割を編集する機能ではない。

振動3Dは`requestAnimationFrame`ごとに時刻をshaderへ渡すため、60Hz／120Hzなど端末とブラウザの実効描画更新へ追従する。120fpsをコード側で固定保証はしない。自動振動は約8Hz、テクスチャUVの最大振幅は横0.35%、縦0.16%とし、`prefers-reduced-motion`が有効な場合は振動成分だけを0にする。顔／指による前景視差は維持する。

## 2. カメラ・顔追跡の開始順

```text
ボタンのユーザー操作
  ↓
Secure Context / mediaDevices確認
  ↓
getUserMedia(facingMode: user)
  ↓
video.play()
  ↓
MediaPipe JavaScript module + WASM + model読込
  ↓
GPUでFaceLandmarker生成
  ├─ 成功 → VIDEO検出
  └─ 失敗 → CPUで再生成
```

カメラ要求を外部モジュール読込より先に置く。これにより、CDNやWASMが失敗してもカメラ権限処理へ到達し、原因を分離して表示できる。

## 3. 外部依存

|用途|固定参照|
|---|---|
|MediaPipe module|`@mediapipe/tasks-vision@1.0.1/vision_bundle.mjs`|
|MediaPipe WASM|`@mediapipe/tasks-vision@1.0.1/wasm`|

## 4. 状態の分離

- `cameraOn`: カメラstreamとvideo再生が開始済み。
- `trackingOn`: Face Landmarkerが初期化済みでフレーム検出可能。
- `startingFace`: 起動処理の多重実行を防止。
- `hasDepthMap` / `hasSubjectMask`: 任意または人物自動分離で生成した補助テクスチャの有無。
- `nearView` / `midView` / `farView`: 同じ顔／ドラッグ視点へ異なる追従係数を適用した多層視差状態。
- `targetZ` / `viewZ` / `faceScaleBaseline`: 両目間隔から求めた顔の前後移動と平滑化状態。
- `recognitionBounds` / `recognitionGuideCanvas`: 人物／物体マスクから得た確認用ガイド。
- `guideHandles` / `guideDragTarget`: キャラ中心・光源の画面座標とドラッグ対象。
- `undoStack` / `redoStack`: 非破壊編集値の履歴。画像、Depth、マスク本体は含めない。
- `DEMO_ASSETS` / `activeDemoIndex`: 完成絵、背景、透過立ち絵のURL、表示名、推奨中心・範囲・立体強度と現在の選択状態。
- `hasLayeredDemo`: 背景と透過立ち絵の独立テクスチャを使うデモ状態。無効時は従来の単一画像経路を使う。
- `activeRigProfile` / `activeRigParts` / `activeMotionRange`: 全2層デモの基準影響域、編集可能な最大8部位と親子・モーション設定、接地点、背景内の許容稼働範囲。
- `activeStandee`: アクスタ固有のアクリル材質表現だけを有効にする現在デモの状態。Live2D風モーションの有効条件には使わない。
- `rigSprings`: 胴体、頭、髪・布、小物それぞれの位置と速度。画像データや編集履歴には含めず、デモ切替時にゼロへ戻す。
- `inferredRigProfile` / `inferredRigParts`: 現在素材から得た自動推定の基準値。編集後の状態と比較して手動補正状態を表示し、部位単位の復元元に使う。
- `RIG_PARTS` / `MOTION_PRESETS` / `live2dVisualState`: 標準TAGの表示名・色、部位別アルゴリズムの初期物性、瞬き／口元／視線／呼吸の現在値。デバッグoverlayは`rigSprings`と併せて毎フレーム参照する。
- カメラ失敗: 手動モードへ戻してカメラ再試行を提示。
- 顔検出準備失敗: カメラを停止せず、手動操作と顔追跡再試行を提示。
